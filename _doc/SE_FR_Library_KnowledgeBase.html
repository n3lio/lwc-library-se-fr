Design principles

  • Lightning base components first. lightning-card, lightning-button, lightning-datatable & co. are translated by the platform — we use them wherever possible.
  • Custom strings become properties. Anything that could reasonably need renaming is an @api with a French default.
  • Demo data as JSON / CSV props. Dashboards with mock KPIs accept those as stringified JSON / CSV so SEs can swap the dataset in App Builder.
  • Currency & locale exposed. currencyCode (default EUR) and localeTag (default fr-FR) are properties.
  • Standard fields first. The library uses only Salesforce standard fields by default. No mandatory custom field.
  • Schema-safe Apex. Where an optional custom field can enrich the UI, Apex checks for its existence before referencing it — deploys succeed regardless.
  • Bilingual FR / EN. Every component exposes a language prop with FR/EN dictionaries baked in.

Reading a component page

Each component page carries:

  • Name — human name displayed in the App Builder master label. Example: Account Health.
  • API name — technical LWC identifier in camelCase. Example: seFrAccountHealth.
  • Tagline — one-line pitch, what you’d use to sell the component in 5 seconds.
  • Chips — 3-4 wow features. Examples: SVG donut gauge, Native drag & drop, 4 chart styles.
  • Status badges — labels at the top of the page. Examples: ● Stable, ✨ New, 🤖 AI-ready, 📱 Mobile-ready, No Apex.
  • Personas — target teams. Examples: 📌 Sales, 🚗 Field Sales, 📞 Service, 🤖 Agentforce.
  • Targets — page types where the component can land. Example: Home · App · Record.
  • Objects — supported SObjects on Record Pages. Examples: Account, Contact / Lead / Account, Any.
  • Apex — optional Apex dependencies, local or shared. Examples: SE_FR_AccountHealthController, SE_FR_ImageFileController (shared), none.
  • Data mode — how the component behaves towards org data. Values: live (reads/writes real records), hybrid (real if present, else mock), mock (100% prop-driven, no org dependency).
  • Pitch — short paragraph that fleshes out the tagline.
  • SE benefit — the demo angle that lands, the moment the prospect looks up from their screen.
  • Configurable settings — 3-5 key props to tune in App Builder. Examples: chartStyle, seriesJson, currencyCode.
  • All properties — full table (name, type, default, description) read straight from the component’s js-meta.xml.
  • Quick install — the 4 deploy methods (Deploy button, CLI, AI assistant, Lightning Studio).
  • Original author / Maintained by — original author and library maintainer (shown when an external contributor wrote the component).
  • Categories — the library category the component belongs to. Examples: Sales, Service, Productivity.
  • Featured in cookbook — Cookbook recipes that bundle this component.
  • Often used with — components of the same category typically dropped together.

Library standards, install methods, configuration, data setup

Quick install

Every component is a self-contained zip — LWC bundle plus dedicated Apex and any shared Apex it depends on. The fastest path:

  1. Browse to Components and pick what you need.
  2. Click Connect to my org in the top right — OAuth flow into your demo org.
  3. Click Deploy on each component (or bundle them in the cart).

Named Credential setup

A few Agentforce-related components — typically seFrPromptLauncher, and the "Summarize" button on seFrContactCard / seFrSmartRecommendations — make authenticated REST callouts to the org’s Salesforce API to run Prompt Templates. Without a Named Credential, these calls fail.

The expected Named Credential is Agentforce_API (library convention). It’s used to reach any /services/data/... endpoint of the org: Prompt Templates, Agent API, custom REST.

Setup ~10 minutes, done once per org. The chain: Connected App (scopes api chatbot_api refresh_token einstein_gpt_api) → Salesforce-type Auth Provider reusing the Connected App credentials → OAuth 2.0 / Browser Flow External Credential pointing to the Auth Provider → Permission Set mapping the External Credential principal to your user → Named Credential Agentforce_API pointing to https://<your-domain>.my.salesforce.com via the External Credential.

Common pitfalls: PKCE is checked by default on both the Connected App AND the Auth Provider — uncheck on both. External Credential requires Spring ’23 or later. Permission Set mapping is done via the External Credential Principal Access section, not via Object/Field permissions. The Named Credential name must match Agentforce_API exactly (case-sensitive).

Quick test from the Developer Console:

HttpRequest req = new HttpRequest();
req.setEndpoint('callout:Agentforce_API/services/data/v62.0/actions/custom/generatePromptResponse');
req.setMethod('GET');
HttpResponse res = new Http().send(req);
System.debug(res.getStatusCode() + ' ' + res.getBody().abbreviate(500));

Should return 200 + the prompt list. 401/403 = re-check External Credential / Permission Set. 404 = wrong URL. "Named Credential not found" = NC missing or misnamed.

Permission Sets for the running user

On top of the custom Agentforce_API_Access permset (which opens the External Credential), assign these standard Salesforce permsets to the user who needs to run the Prompt Templates:

  • EinsteinGPTPromptTemplateUser — run Prompt Templates from UI and Apex.
  • Agentforce_API_Access — the custom permset from the tutorial above, mapping the External Credential principal to the user.
  • EinsteinGPTSalesSummaries (optionnel) — enhances some Contact / Opportunity summaries.

For seFrContactCard in AI Summary mode and seFrPromptLauncher, here are example standard Prompt Template API names to set on the promptTemplateApiName prop:

  • einstein_gpt__summarizeContact — Contact summary (AI-enriched memo).
  • einstein_gpt__summarizeRecord — generic summary for Account / Opportunity / Case.

A few components can use custom fields specific to the Cust360 SDO (customer signals) or MAPS (field visits). When absent, the component silently falls back to mock — no crash, no error.

  • seFrAccountHealth — optionally uses NPS__c and SDO_MAPS_Days_Since_Last_Visit__c to enrich signals. Without these, the score is computed from standard fields only (AnnualRevenue, LastActivityDate, Open Cases, Orders).

Components that display images (seFrRecordHighlights, seFrContactCard, seFrRelatedRecordCard, seFrFilesGallery) use ContentDocument attached to the record — not Static Resources or org-specific ImageURL__c fields.

Prerequisites — user timezone

Date.today() in Apex and TODAY / THIS_WEEK SOQL filters resolve against the running user's timezone, not the org timezone. Most Salesforce SDOs ship with the org set to America/Los_Angeles — if your user also inherits that timezone, a 09:00 Paris meeting stored as 07:00Z will appear as 00:00 and today's events may be picked up under yesterday or tomorrow.

Before using the component, make sure your user's timezone matches your local time:


  • Setup → Personal Information → Time Zone → pick your local value (e.g. (GMT+01:00) Central European Time (Europe/Paris) in winter / (GMT+02:00) Central European Summer Time (Europe/Paris) in summer).

  • Save, refresh the tab.

You don't need to change the org timezone (Setup → Company Information) — that has much broader side-effects (Business Hours, Reports, audit trails). Changing only the user timezone is the standard SE practice on a shared SDO.

Known caveats — external calendars (Gmail / Outlook)

Salesforce surfaces Gmail / Outlook events in the standard calendar via Einstein Activity Capture (EAC), which stores them in a private dataset that's not queryable via SOQL (Event only contains records created inside Salesforce). This means the component cannot show EAC-synced meetings — no LWC on the platform can. To still have external meetings visible here, either:
  • manually create the meeting as a Salesforce Event, or
  • use the Lightning for Outlook / Gmail "log email / event" action which creates a real Event record.

Other caveats

  • Events longer than the visible timeline are clipped to the effective bounds (the block fills from the visible portion only).
  • Join-URL detection is a regex over Location + Description; custom URLs won't be detected.
  • The "now" line refreshes every 60 seconds. If the component sits hidden in a tab for a long time, it picks up the next minute on re-render.

Voice recognition relies on window.SpeechRecognition / webkitSpeechRecognition. Works in Chrome, Edge and Safari — Firefox shows the unsupported-browser message.
